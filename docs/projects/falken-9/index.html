Falken-9

A neural network designed for the Commodore 64

A mixture-of-experts tic-tac-toe model trained for the Commodore 64 from the start: a 5,195-byte model that stays in RAM and now lets Crystal Palace 9 play a complete AI-vs-AI game in just over a minute.

Executive summary

Why it exists

Crystal-9 proved a learned network could run on a C64, but its weights had to be paged from disk and a self-play game took roughly 20 minutes. I wanted a network designed around the C64's arithmetic, memory and responsiveness, small enough to verify and investigate exhaustively, without hiding a move table or minimax behind it.

Outcome

A 5,195-byte model packet with all 627 canonical boards passing assembled numerical checks. Crystal Palace 9, now powered by Falken-9, plays a complete AI-vs-AI game in just over a minute in an emulator, down from about 20 minutes with the earlier model. The project ships a ready-to-run PRG and D64, an exact-integer ONNX graph for Netron, a tensor-workflow chart and a research report with annotated figures. Tested in emulators only so far.

My role

Designer, director and maintainer. AI agents (GPT-6.1 Sol through Hermes Agent) ran the training, integer conversion and probing work I directed; PyTorch did the heavy lifting.

Technical overview

How it works

Falken-9 searches model width, expert count and numerical precision against the whole deployment cost on the C64. The accepted model has nine board-square tokens, width 8, four learned experts with top-2 routing, real full-board attention and exact integer execution in 6502 assembly. Symmetry reduces the learned domain to 627 canonical boards; a fixed wrapper restores the original board, masks occupied squares and applies a documented tie order. The whole model stays in RAM, and every AI move runs it.

Hard parts

Keeping it honest. The network predicts the complete set of optimal moves, because mapping one canonical move back would break tie behavior. Offline minimax supplies labels and checks but is never a gameplay fallback, and exact logits, packed arithmetic, chosen moves and whole games each have their own evidence gate. Interpreting the network was its own project: the research report probes it with interventions and counterexamples, and found context-dependent effects rather than a tidy fork expert or block neuron.

How it was made

Built October 31 to November 1, 2026. Hermes Agent delegated the training, integer conversion and probing to GPT-6.1 Sol workers (openai-codex provider). Training used Python and PyTorch with AdamW: early experiments on an RTX 3080 Ti compared float, binary and ternary candidates, and the compact models trained on a single CPU thread with binary cross-entropy over the complete set of optimal moves. Falken-9 was trained from scratch, not fine-tuned from Crystal-9, and the 5,195-byte integer packet came from direct conversion with no extra training.

Probing ran on the CPU against frozen weights, not by another model judging answers: linear readouts with held-out splits and shuffled-label controls, ablations, dose-response tests, activation patching, paired lesions, and attention, router and gate interventions. Integer forwards were checked against an independent arbitrary-integer oracle across 627 canonical positions, 4,520 boards and 294,778 histories. C64 execution was checked with 64tass, py65 and VICE; inspection used ONNX Runtime, Netron and Pillow, with pytest for the tests.
