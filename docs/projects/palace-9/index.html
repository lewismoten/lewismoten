Palace-9

Local model inspection

A playable tic-tac-toe lab that pairs a deterministic controller with a compact MoE model trained from scratch, and a browser inspector that reads the checkpoint locally.

Executive summary

Why it exists

I wanted to look inside a small model, not only run it. That meant keeping two things separate: a perfect-play controller for the game, and a trained model that reads raw move histories.

Outcome

A live demo, a published Ollama model, and a Hugging Face release.

My role

Author and maintainer.

Technical overview

How it works

A 3x3 simulation with 0-, 1-, and 2-player modes. A deterministic minimax policy in browser JavaScript is the perfect-play oracle. A separate compact causal model uses the Qwen2-MoE architecture, so it works with Ollama and llama.cpp without a custom fork. The browser decodes the packed FP32, F16, Q6_K, or Q4_K_M release artifact locally and computes a forward trace from its weights.

Hard parts

Keeping real and fictional parts apart. The site never calls Ollama; its board moves come from the local oracle, and the visualizer is a local trace. The map, DEFCON strip, trajectories, and cipher are labeled visual fiction. My September post on the project describes the visualization, training, and tokenizer problems I hit, and how they led to the smaller Crystal-9.

How it was made

Palace-9 started as a model trained in the web browser; then I moved training to PyTorch on my GPU. Along the way I learned to publish models and make them run on Ollama. With no control over the token set, the first model was very large, so I worked it down to the smallest vocabulary possible. The architecture follows Qwen2-MoE only so that Ollama knows how to run its mixture of experts; it is not a Qwen model.

The website has a Cold War theme, after Crystal Palace, the NORAD call sign in WarGames where an AI plays against itself. The computer plays itself over maps of the USA and USSR, missiles launch with each player's mark and speed up as the game goes on, and a launch code is worked out digit by digit, but the last digit never locks in.
